# Release 2.5 KPI dictionary

Source: `portal/reporting.py`. All request counts are limited to the caller's authorized scope and selected filters. `N` means requests with non-null `submitted_at` inside the inclusive local-date period; Draft is excluded. `O` is `N` excluding Completed, Rejected and Cancelled. `C` is current Completed within `N`. `E` is `N` excluding Rejected/Cancelled. Unless explicitly marked “completion event,” each metric uses the **submission cohort** `N` and current request state. A zero denominator is displayed as “نامشخص,” not 0%. Percentages are rounded to one decimal.

`working(a,b)` uses seconds within the active WorkingCalendar workday, excluding weekends and non-working dates; without an active calendar it is elapsed wall seconds. `provider(end) = working(submitted_at,end) − working(union(pauses))`. Pauses are recorded CLOCK_PAUSED→CLOCK_RESUMED intervals and ApprovalSteps with `pauses_sla=True`, clipped to the measured interval. The union prevents double subtraction. Local timezone is used at period boundaries. Legacy rows with missing Program/Project remain in Total and are labeled `قدیمی / نگاشت‌نشده`.

| KPI / display | Formula and numerator / denominator | Statuses and time basis | Pause / calendar / null / legacy handling |
| --- | --- | --- | --- |
| Total Requests, New Requests, new trend | `|N|`, count / none. Trend groups submission dates into 1, 7 or 30-day bins. | All submitted current statuses, including Rejected/Cancelled; Draft excluded. | No duration. Missing snapshots retain row with fallback. |
| Open Requests, Backlog | `|O|`, count / none. Cohort open count, not all older open requests. | Current nonfinal statuses in submission cohort. | No duration; missing Program/Project included. |
| In Progress; Pending hold | Count of `N` with IN_PROGRESS; separately count `provider_hold=True`. | Current status/hold in submission cohort. | Missing case rows do not imply hold. |
| Completed Requests | `|C|`, count / none. | Current Completed in submission cohort, even when completed later. | Missing completion timestamp still counts, but has no resolution duration. |
| Completion Rate | `100×|C|/|E|`. | Current Completed numerator; Rejected/Cancelled excluded denominator. | Zero eligible count → unavailable. |
| Completed in Period, throughput trend | Count of submitted, currently Completed requests with `completed_at` inside period; count / none. May include older submission cohorts. | Completion event basis. | Missing completion date excluded; historical label filters honored. |
| Net Backlog Change | New Requests − Completed in Period; signed count / none. | Combines submission and completion event streams. | A flow indicator, not the difference in cohort open count. |
| Overdue Open | Count in `O` whose consumed provider time exceeds first-response working budget when unanswered, otherwise completion working budget. | Open at generation time; count / none. | Pauses unioned; missing/zero deadline budget is not overdue. |
| At Risk | Count in `O` with consumed/budget ≥ `REPORT_AT_RISK_RATIO` (default .8), not already overdue. | Open at generation time; count / none. | Same working calendar and pause union; missing budget not at risk. |
| First Response average, median, P75/P90 | Statistics of `provider(first_response_at)` for records with first timestamp. Average = duration sum / number with first response; median is middle order value; percentiles use linear interpolation at `(n−1)×p`. | Submitted cohort, any current status with recorded first response. | Working time minus eligible pauses; missing timestamp excluded. P75/P90 require ≥5 samples. |
| Resolution / End-to-end Lead Time average, median, P75/P90, distribution | Wall seconds `completed_at−submitted_at` for Completed with completion timestamp; mean sum / valid duration count, order statistics as above. Histogram ranges <2, 2–5, 5–10 and ≥10 calendar-day equivalents. | Current Completed in submission cohort. | Includes all waits; pauses and calendar do not alter end-to-end time. Missing completion excluded from duration. P75/P90 require ≥5. |
| Provider Operational Time | Average `provider(completed_at)` for Completed, sum / Completed count. | Current Completed in submission cohort. | Calendar and pause union apply. Missing completion makes operational duration provisional. |
| Waiting for Requester | Average working seconds from recorded NEED_INFO CLOCK_PAUSED to resume/end, sum / requests with positive recorded wait. | Event duration among `N`. | Calendar used; absent event → no wait; same pause reduces provider time. |
| Program / Senior Approval Wait | Average wall seconds of corresponding ApprovalStep targets from start to decision/now, sum / requests with positive wait. | Step duration among `N`. | Missing start excluded. Only pausing steps reduce provider SLA; displayed waits can overlap. |
| First Response SLA | `100×count(first_sla=True)/count(first_sla known)`. Response provider time ≤ working budget from submission to stored initial deadline; unanswered request enters after deadline. | `N` excluding Rejected/Cancelled. | Calendar and pause union; missing/zero budget and unanswered immature deadlines excluded. |
| Completion SLA | `100×count(completion_sla=True)/count(completion_sla known)`. Completion provider time ≤ working budget to stored latest delivery date; open request enters after deadline. | `N` excluding Rejected/Cancelled. | Calendar and pause union; missing/zero budget and open immature deadlines excluded. |
| Aging buckets | Count of `O` by local **calendar days** since submission: 0–2, 3–5, 6–10, 11–20, ≥21. | Current Open in submission cohort. | Pauses do not stop age; missing submission excluded from cohort. |
| Approval Requests, Pending, Approved, Rejected | Count linked ApprovalCase rows by current status, possibly multiple per request. Group by trigger type, Program, Department. | Cases linked to `N`; current case status. | Missing cases count zero, no duration. |
| Approval Rate | `100×approved/(approved+rejected)` final cases. | Linked cases in `N`; pending/clarification excluded from denominator. | Zero final decisions → unavailable. |
| Average Approval Wait | Mean Program + Senior step waits for requests with positive wait; sum / positive-wait requests. | Approval event durations linked to `N`. | Wall seconds; missing start excluded. Provider subtraction uses union only for `pauses_sla`. |
| Emergency, Very Urgent, Priority distribution | Counts by stored priority among `N`; count / none. | All submitted current priority values. | No duration. Later edits change live grouping. |
| Credit Allocation, Reserved, Consumed, Released, Remaining | Allocation quantity and reservation status counts per **Program × Department × Priority × Allocation Period** wallet; remaining `max(0,quantity−reserved−consumed)`. | Wallet periods intersect selected period; filters apply. Not the request submission cohort. | No wallet means no row, not a fabricated zero allocation. Released does not occupy capacity. |
| Credit Utilization | `100×(reserved+consumed)/quantity` per wallet. | Allocation period intersection. | Zero quantity → unavailable. No “good/bad” ranking. |
| Department, Program, Project, Family, Service, Owner and Status workload; Program × Department | Count, open, completed, overdue, completion SLA and resolution per group of `N`. | Same cohort and individual formulas above. | Snapshot labels where present; ID is current associated entity; unmapped demand explicit. |
| Request flow | Five illustrative counts: Submitted without provider hold; Review/Need Info/Accepted/On Hold; provider hold; In Progress; Completed. | Current statuses and hold among `N`. | These stage bars are not an exhaustive partition: Rejected/Cancelled remain in Total. |
| Previous-period changes | Current KPI minus corresponding KPI of immediately previous equivalent elapsed window with identical filters. | Each window's submission cohort and current statuses. | Rate change unavailable if either denominator absent. Jalali preset starts use Jalali boundaries. |

The PDF and Excel reuse these definitions. Excel emits raw timing seconds and status flags; no unseen formula is applied in a download. Pre-snapshot catalogue labels may fall back to current related names; historical definitions that were not saved cannot be reconstructed.
